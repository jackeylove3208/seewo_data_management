## Why

现有后端已经具备 CSV 数据接入、实体解析、差异检测和强制 AI 分析的基础能力，但前端仍使用演示差异，四个阶段也没有形成可恢复的自动链路。AI 分析目前只返回单一建议，真实企业模型配置、敏感字段令牌化、方案选择和人工治理方案也尚未形成完整产品能力。

## What Changes

- 将任务创建后的数据接入、实体解析、差异检测和 AI 强制分析编排为连续流程，并持久化阶段状态、进度和可重试错误。
- 用真实的 OpenAI 兼容企业模型网关执行语义分析；通过后端环境变量配置 URL、API Key、模型、超时、重试、结构化输出模式、额外请求头和经过校验的额外请求体。
- 在所有模型初始上下文和 MCP 查询结果发出前，对姓名、电话、邮箱和外部标识等敏感值执行任务级稳定令牌化，不把令牌映射写入模型日志或分析溯源。
- 将 AI 分析升级为可返回一至三个经过业务规则校验的治理方案；信息不足、无可靠动作或风险过高时允许只返回人工处理建议。
- 将前端任务详情和差异页从演示数据切换到真实 API，展示四阶段状态、AI 分析动画、批量进度、失败和重试状态。
- 新增逐条差异的 AI 方案弹窗，展示成因、证据、风险、置信度和候选方案；用户可以选择 AI 方案或进入人工编辑器。
- 人工编辑器按实体类型只开放规范字段白名单，展示修改前后值并要求填写修改原因。
- AI 选择和人工修改都在后端保存为不可变的“待治理执行方案”，不直接写入希沃 CSV 或未来的希沃 API；后续治理执行模块读取该方案完成预览、预检、确认和执行。
- **BREAKING**：任务租户从后端认证上下文获取，前端不再提交或决定 `tenant_id`，避免跨租户查询失败和身份伪造。

## Capabilities

### New Capabilities

- `reconciliation-workflow-orchestration`: 编排数据接入后的实体解析、差异检测和强制 AI 分析，持久化阶段进度、错误和重试语义。
- `enterprise-model-gateway`: 通过可配置企业模型网关执行结构化分析，并统一实施令牌化、响应校验、溯源和安全配置。
- `ai-governance-proposal-workbench`: 提供真实差异工作台、AI 分析动画、多方案弹窗、人工白名单编辑和待执行方案持久化。

### Modified Capabilities

无。主规格目录尚未包含已同步能力；本变更以独立增量能力描述对现有 `demo` 实现的扩展。

## Impact

- 后端将新增工作流编排、令牌化、分析 v2、方案持久化和对应 REST API，并调整任务创建的租户边界。
- `HttpLLMProvider` 将扩展为企业网关适配器；真实凭据写入被 Git 忽略的 `backend/.env`，示例和值说明写入 `backend/.env.example` 和开发文档。
- 前端将新增任务、差异、分析和方案 API 客户端，并重构任务详情与差异页以使用 TanStack Query 管理真实服务状态。
- 数据库需要新增或扩展分析方案、治理方案和阶段进度字段，并提供 Alembic 迁移。
- 测试将覆盖真实 HTTP 协议契约的本地假网关、令牌泄漏检查、自动阶段推进、多方案校验、人工方案、租户隔离和前端端到端链路；自动化测试不调用收费的外部模型。
