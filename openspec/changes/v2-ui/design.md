## Context

当前 React 应用通过 `WorkspaceSidebar` 提供一个“新建对账”入口，`TaskCreatePage` 同时承担 AI 对话、CSV 摘要、任务草案编辑和最终任务创建。桌面端因此形成聊天区与右侧草案面板的并列布局，移动端也必须承载同一组混合职责。

V2 UI 将目标描述和外部数据接入视为两个连续但可独立进入的操作：用户可先通过“新建对话”整理任务意图，也可直接进入“外部数据同步”使用默认信息完成 CSV 对账。现有 `createTaskFromDraft`、CSV 摘要、历史更新、后端 API 和任务详情阶段不得改变。前端已有大量未提交的 AI 工作流修改，本变更实施时必须仅处理 V2 UI 相关文件并与这些修改共存。

## Goals / Non-Goals

**Goals:**

- 在左侧工作台提供清晰、同级的“新建对话”和“外部数据同步”入口。
- 让对话页只维护非文件任务草案，并能把草案可靠地交给外部数据同步。
- 让外部数据同步先显示“手动同步”，激活后才显示成对 CSV 和任务表单。
- 复用当前任务创建服务和下游四阶段流程，不产生第二套请求路径。
- 建立安静、专业、响应式且无布局跳动的企业工作台视觉系统。

**Non-Goals:**

- 不提供、展示或预留自动同步和增量同步。
- 不接入真实第三方系统、希沃宿主 API 或新的后端连接器。
- 不修改数据接入、实体解析、差异检测、AI 分析或治理执行的后端行为。
- 不引入新的全局状态库、设计系统依赖或模型适配器。
- 不重做任务列表、任务详情和差异页面的信息架构；仅调整共享视觉变量时保持其行为稳定。

## Decisions

### 1. Split the current creation page into two routes

新增独立对话路由 `/conversations/new`，保留 `/tasks/new` 作为“外部数据同步”。`WorkspaceSidebar` 将两个入口放在历史记录之前，使用不同的 Lucide 图标、直接文本、当前路由样式和无障碍名称。任务列表中的“新建对账”文案同步改为“外部数据同步”。

选择两个独立路由而不是在同一页使用标签页，是因为它们拥有不同完成条件、错误状态和主要操作。独立路由也能让浏览器返回、侧栏选中状态、移动抽屉关闭和自动化测试保持明确。未选择把“新建对话”做成禁用占位，因为用户已确认它需要生成并交接真实草案。

### 2. Separate task intent from file-backed sync state

将现有混合 `TaskDraft` 拆分为两个概念边界：

- `TaskIntentDraft`：标题、范围、实体类型和 `full/partial` 模式，由对话页创建和编辑。
- `ManualSyncDraft`：包含一个 `TaskIntentDraft` 以及 source/target CSV 附件、摘要和文件错误，只由外部数据同步页持有。

对话页将不渲染 CSV 控件，也不调用 `createTaskFromDraft`。草案交接使用一个小型、版本化的 `sessionStorage` 适配器，仅保存可序列化的非文件字段；外部同步页读取草案作为初始值，直接进入时使用 `createInitialDraft()` 的现有默认字段。成功创建任务或显式开始新对话时清除旧交接草案，避免后续同步意外复用过期意图。

选择浏览器会话存储而不是仅用 React Router location state，是为了让同步页刷新后仍保留对话草案；选择会话存储而不是全局状态库，是因为当前只存在一个浏览器内交接边界，新增依赖没有收益。CSV `File` 对象和摘要不写入存储。

### 3. Model external sync as an explicit two-state page

外部数据同步页只有两个页面状态：

1. `entry`：显示页面标题、简短同步上下文和唯一的“手动同步”命令；没有自动同步、CSV 控件或任务表单。
2. `manual`：显示一个连续的操作表单，包括双方 CSV、任务名称、范围、实体类型、处理模式、校验反馈和“开始同步”。

状态只控制前端显示，不加入后端请求字段。选择显式入口状态而不是直接显示表单，是因为用户要求先确认手动同步再拉取 CSV，同时为操作员建立清楚的数据来源边界。由于没有第二种方式，界面不使用分段选择器或方法对比卡片，也不显示“自动同步暂未开放”。

### 4. Reuse the existing task creation boundary

手动表单将 `TaskIntentDraft` 与两个有效附件组合为当前任务创建服务需要的结构，继续使用相同幂等键完成成对上传、任务请求、历史刷新和成功导航。提交期间锁定主要操作；失败时保留文件、摘要、字段和幂等键以便安全重试。

不复制上传逻辑到新页面。若当前 `TaskCreatePage` 中存在可复用的附件选择或草案字段组件，则提取为聚焦组件；任务服务接口保持不变。成功后仍进入 `/tasks/:taskId`，由现有工作流显示数据接入、实体解析、差异检测和 AI 分析。

### 5. Use a quiet, balanced enterprise visual system

V2 采用浅色中性画布和清晰的功能色，而不是深色单色主题或营销式构图：

- 以白色和中性浅灰承载页面，正文使用近黑中性色；蓝色标识对话意图，绿色标识数据同步，琥珀色用于等待/提醒，红色仅用于错误。
- 左侧工作台保持紧凑、稳定宽度，两个主要命令具有一致尺寸但不同图标和当前状态；历史列表保持高信息密度。
- 页面标题使用工作台级字号，不使用占据首屏的 hero 字号；字距固定为 `0`。
- 主内容采用无框的全宽页面带和约束宽度内容区。仅文件选择器、重复数据摘要和真实工具区域使用浅边框容器，不嵌套卡片。
- 操作使用 Lucide 图标；二元实体选择继续用复选框，处理模式使用分段控件，文件选择使用明确的上传区，数值和状态使用直接标签。
- 控件高度、图标按钮、导航行和摘要网格使用稳定尺寸，加载、校验、悬停和错误文本不得改变主要布局宽度。
- 过渡限制在颜色、边框和小幅透明度变化，并尊重 `prefers-reduced-motion`；不使用渐变光球、装饰背景或与业务无关的插画。

视觉变量集中在 `global.css` 的语义 token 中，优先复用 Ant Design 控件的主题能力和现有类名边界。共享 token 的调整必须同时检查任务列表、任务详情和差异页面，避免局部美化造成全局回归。

### 6. Preserve responsive and accessible navigation

桌面展开侧栏显示图标和文本，折叠侧栏显示稳定图标宽度、tooltip 和 `aria-label`。移动端继续使用现有抽屉；选择任一入口后关闭抽屉并让目的页面标题成为逻辑阅读起点。

同步页桌面使用单列约束宽度，文件区可在足够宽时并排；窄屏全部纵向排列。所有文件输入、实体复选框、模式控件、错误消息和提交状态具有直接可访问名称。错误使用 `aria-live` 或关联描述，焦点样式不得仅依靠颜色表达。

## Risks / Trade-offs

- [会话草案可能过期或结构升级后无法读取] → 为存储载荷增加版本号和运行时校验；无效载荷直接丢弃并回退默认任务信息。
- [拆页后从对话到创建任务多一次导航] → 使用明确的“继续外部数据同步”主操作并自动带入所有非文件字段，使额外步骤对应真实的数据接入边界。
- [外部同步只有一种方式却需要额外点击] → 保留用户明确要求的 `entry → manual` 状态，并让入口动作显著、反馈即时，不增加无意义说明或方法比较。
- [全局视觉 token 改动影响已完成页面] → 将大部分新样式限定到 V2 页面与侧栏，运行全量前端测试并对任务列表、详情和差异页面做桌面/移动视觉检查。
- [现有前端文件存在并行未提交修改] → 实施前记录工作树状态，限定修改范围，逐文件合并现有变更，不重置或覆盖非 V2 UI 工作。

## Migration Plan

1. 先增加草案类型、会话存储适配器和聚焦测试，不改变现有路由。
2. 增加独立对话页和外部数据同步页，复用现有任务创建服务。
3. 切换路由和侧栏双入口，更新任务列表文案及自动化测试。
4. 应用 V2 视觉 token 和响应式样式，完成桌面与移动视觉校验。
5. 运行前端单元测试、lint、类型检查、生产构建和聚焦 Playwright；确认后端请求和任务详情阶段无变化。

回滚时恢复原 `/tasks/new` 组件和单一侧栏入口即可；会话存储中的非文件草案可被旧版本忽略，不涉及数据库或 API 回滚。

## Open Questions

无。外部数据同步仅包含手动同步、新建对话可实际生成草案、直接同步使用默认任务信息，以及后续处理链路不变均已确认。
