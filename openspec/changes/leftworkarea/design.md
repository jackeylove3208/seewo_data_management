## Context

当前 React 应用由 `AppLayout` 渲染顶部导航，品牌、唯一主导航、连接状态和“新建对账”按钮都位于 `app-header`。任务历史只存在于 `/tasks` 页面，新建任务 `/tasks/new` 使用双方 CSV 上传表单；任务详情和差异页面通过路由独立展示，并依赖返回按钮回到列表。

新的产品方向只借鉴 DeepSeek 左侧导航的空间组织方式，不复制通用聊天产品。左侧工作区需要持续展示产品入口、新建对账、历史任务摘要和连接状态，右侧仍是组织数据治理工作台。新建对账的主内容改为 AI 对话，但现有确定性上传、任务创建、差异审核和回退链路必须继续工作。

本变更与 `demo` 变更并行。希沃宿主数据未来可通过内部连接器提供，但其接口、CSV 替代策略和写入实现不属于本次 UI 改造。

## Goals / Non-Goals

**Goals:**

- 用常驻左侧工作区取代顶部导航，并使所有现有路由共享同一个稳定壳层。
- 让用户从侧栏快速新建对账、打开最近任务、识别当前任务和查看连接状态。
- 用 AI 对话收集创建任务所需信息，并以结构化草案作为人工确认门槛。
- 保持历史任务可点击、浏览器和页面返回行为可预测，保留差异分类及逐人逐问题勾选流程。
- 在桌面和窄屏下保持主内容可读、按钮可操作且不发生遮挡。
- 通过适配接口隔离对话 UI 与未来小模型实现，使当前阶段可用确定性测试替身完成验证。

**Non-Goals:**

- 不实现、选择或部署具体小模型，不定义模型训练方案。
- 不实现希沃宿主连接器，不取消或重写现有 CSV 后端接口。
- 不允许模型直接执行治理写入、确认差异、生成操作人身份或触发回退。
- 不重做任务详情、差异表格、人员问题选择、执行历史和回退页面的业务规则。
- 不模仿 DeepSeek 的模型模式、搜索、账号体系或通用会话能力。

## Decisions

### 1. Build one persistent application shell

`AppLayout` 改为两列应用壳层：左侧 `WorkspaceSidebar`，右侧 `WorkspaceMain`。桌面侧栏使用固定宽度并独立滚动历史区域，主内容使用 `minmax(0, 1fr)`，现有页面继续通过 React Router 渲染到主内容区。

侧栏从上到下固定为：产品标识、收起/展开按钮、主要命令“新建对账”、历史任务区和底部连接状态。历史任务只显示标题、时间/状态和问题数等直观摘要，不显示文件哈希、快照 ID 或内部版本号。当前路由对应的任务使用选中状态，并通过 `aria-current` 暴露给辅助技术。

选择该方案是因为侧栏是跨页面导航，不应由各业务页面重复实现。替代方案是在任务列表页增加一个左栏，但进入任务详情后上下文会消失，因此拒绝。

### 2. Preserve routes and derive navigation state from the URL

保留 `/tasks`、`/tasks/new`、`/tasks/:taskId` 和差异详情路由。侧栏不维护另一份“当前任务”状态，而是根据 URL 参数确定选中项；点击历史摘要直接进入对应任务详情。现有返回按钮继续调用浏览器历史，在没有有效历史时回退到任务详情或任务列表。

`/tasks` 仍作为完整任务列表和统计页，侧栏按时间倒序展示最近 8 条任务且不额外按日期分组，并提供进入全部历史的简洁入口。这样既保留可扫描的完整列表，也不会让侧栏承担复杂筛选表格。

替代方案是把历史列表完全移入侧栏并删除 `/tasks`，但侧栏空间不足以承载统计、状态和后续筛选，因此拒绝。

### 3. Use a responsive sidebar, not a permanently narrow content column

桌面宽度下侧栏默认展开，并允许折叠为只显示图标的窄栏；折叠状态保存在浏览器本地。窄屏下侧栏变为覆盖式抽屉，由主内容顶部的菜单图标打开，路由变化或选择任务后自动关闭。抽屉打开时需要焦点约束、关闭按钮和遮罩，关闭后焦点返回触发按钮。

主内容区域维持现有页面的最大宽度约束，但宽度计算从视口改为可用工作区。固定格式表格继续使用响应式列或水平滚动，不能被侧栏挤压到文字重叠。

### 4. Model task creation as a guarded conversation state machine

新建页面使用以下状态：

```text
idle -> collecting -> draft-ready -> submitting -> created
                    \-> needs-input
submitting -> failed -> draft-ready
```

对话助手逐步收集三方系统 CSV、希沃魔方 CSV、对账范围、实体类型和处理模式。处理模式严格映射到后端已有的 `full`（全量对账）与 `partial`（指定范围），本次不引入 `incremental`。当前后端仍要求的文件与映射信息由现有创建服务适配层提供；本次不改变后端数据来源契约。每次输入都更新结构化 `TaskDraft`，而不是依赖聊天文本反向拼接请求。

`TaskDraft` 至少包含标题、数据附件状态、范围、实体类型、处理模式、缺失字段和验证状态。只有草案通过前端基本校验后，UI 才展示确认区并启用“创建对账”。最终请求仍由现有上传与任务创建 API 完成，成功后导航到任务详情并让侧栏历史立即刷新。

选择状态机而不是自由聊天，是因为创建任务需要明确、可测试且可恢复的业务字段。替代方案是让模型直接输出 API 请求并立即提交，但这会绕过人工确认并扩大模型权限，因此拒绝。

### 5. Put the model behind a narrow assistant adapter

前端定义 `TaskCreationAssistant` 接口，输入当前结构化草案、用户消息和附件摘要，输出助手消息、字段补丁、仍需追问的字段以及可选的草案就绪标记。UI 不依赖具体模型 SDK。

第一阶段固定使用确定性本地适配器驱动对话，未来小模型通过后端受控端点接入同一接口。适配器输出必须经过结构约束；无效输出显示可重试状态，并保留用户已选择的文件和草案字段。演示模式继续使用固定的非生产租户上下文；生产环境中的租户、操作人、权限和可执行性事实仍须由未来宿主上下文提供。

### 6. Separate conversation from governance authorization

对话助手只能协助创建对账任务。任务创建后，实体解析、差异检测、问题勾选、执行确认和回退仍沿用确定性页面与后端门禁。用户即使在对话中输入“全部修复”或“回退上次任务”，助手也只能解释下一步或引导到对应页面，不能直接发出治理或回退命令。

### 7. Migrate incrementally around existing behavior

实施顺序如下：

1. 提取当前品牌、连接状态和历史任务数据访问，建立可单独测试的侧栏组件。
2. 把 `AppLayout` 从顶部导航改成左右壳层，但保持原路由和页面内容不变。
3. 接入历史任务摘要、当前任务高亮、完整历史入口和桌面折叠/移动抽屉。
4. 提取现有上传与创建逻辑为可复用任务创建服务，避免对话页直接拼装请求。
5. 建立 `TaskDraft`、对话状态机和 `TaskCreationAssistant` 适配接口。
6. 用对话页替换现有 `/tasks/new` 表单，在确认区调用现有创建服务。
7. 迁移页面宽度、返回按钮和表格响应式样式，验证所有现有路由。
8. 补齐组件、路由、错误恢复和桌面/移动端到端测试，再移除旧顶部导航样式。

## Risks / Trade-offs

- [侧栏历史与完整任务列表出现信息重复] → 侧栏限制为最近任务摘要，完整列表继续负责统计、筛选和全量浏览。
- [对话显得像 AI，但无法稳定创建任务] → 使用结构化草案、缺失字段集合和显式确认按钮，不以自由文本作为请求事实来源。
- [当前后端仍要求双方 CSV，与未来宿主模式不同] → 本次通过创建服务适配层隔离数据来源，暂不把宿主连接器设计混入 UI 任务。
- [小模型输出不符合字段要求] → 做运行时校验、错误提示、有限重试和人工编辑草案，不丢失已有输入。
- [侧栏占用横向空间导致表格拥挤] → 使用可折叠侧栏、主区域 `min-width: 0` 和针对固定表格的响应式验证。
- [历史任务数据当前来自本地存储和演示数据] → 侧栏复用统一任务查询函数，后续接真实任务 API 时只替换数据源。

## Migration Plan

1. 在不移除顶部导航的情况下完成侧栏组件测试和视觉基线。
2. 通过应用壳层切换启用左侧工作区，验证全部既有路由后删除顶部导航。
3. 接入历史摘要与响应式行为，保留 `/tasks` 作为回退入口。
4. 提取任务创建服务并用现有表单做回归测试，确认 API 行为未改变。
5. 将 `/tasks/new` 切换到对话页，先使用确定性助手适配器验证端到端创建。
6. 后续小模型可在不改变页面状态机和任务创建服务的前提下替换助手适配器。

若发布后出现导航或对话创建故障，可恢复旧 `AppLayout` 和旧任务创建路由；现有任务数据、差异选择和后端接口不需要迁移或回滚。

## Resolved Questions

- 第一阶段采用纯前端确定性适配器，不调用真实小模型端点。
- 侧栏按最近时间排序展示 8 条任务，不做日期分组，完整历史继续由 `/tasks` 页面承担。
