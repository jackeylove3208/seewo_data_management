# 任务级钉钉临时连接设计

## 背景

当前对话会把租户下已有的钉钉连接作为安全目录提供给模型。只要某个连接处于
`active` 状态，并且权限与可见范围满足任务要求，模型就可以直接选择该连接。前端收到
活动连接卡后只显示“连接测试通过”，不会再次显示 AppKey、AppSecret 或组织范围配置。

因此，用户再次要求“连接钉钉”或发起新的钉钉同步任务时，系统会自动复用后端保存的
连接和凭据，而不是要求用户为本次任务重新授权。

## 目标

- 每次通过 AI 对话发起钉钉同步，都要求用户重新填写完整的钉钉配置。
- 每次提交创建一个独立的任务级临时连接，不覆盖或复用历史连接。
- 临时连接只能用于创建它的当前对话，并且最多绑定一个同步任务。
- 钉钉数据固化为任务快照后尽快撤销凭据；未完成固化的任务在终止后也必须撤销凭据。
- 保留不含秘密的连接和任务审计记录，不保留可供后续任务使用的 AppKey/AppSecret。
- 即使绕过前端直接调用接口，后端也不能使用历史连接创建新的对话同步任务。

## 非目标

- 不改变钉钉 Adapter 的认证、分页、字段投影或错误映射协议。
- 不允许模型或聊天消息接触 AppKey、AppSecret。
- 不改变已有任务冻结连接版本和不可变来源快照的语义。
- 不删除历史持久连接，也不将其转换为临时连接。
- 本次仅约束 AI 对话发起的钉钉同步；其他提供方或独立连接管理入口是否采用临时连接，
  后续另行设计。

## 用户体验

### 发起同步

用户在没有活动任务的对话中提出同步钉钉数据时，系统始终返回钉钉安全配置卡。历史
钉钉连接不作为本次任务的候选项，模型也不再回复“当前仅有一个钉钉连接可用”。

安全配置卡每次重新初始化，不读取上一任务的公开配置或秘密。表单包含：

- 连接名称：系统自动生成并预填，例如 `钉钉临时连接-20260731-143052`，用户可以修改。
- 人员类型：用户重新选择教师或学生。
- 根部门 ID：用户重新填写。
- 人员编号字段：用户重新填写；是否必填继续遵循现有 Provider 配置校验。
- 班级字段：选择学生时显示并重新填写；是否必填继续遵循现有 Provider 配置校验。
- AppKey：必填，使用密码输入框。
- AppSecret：必填，使用密码输入框。

自动名称由服务端生成候选值，以租户内唯一、便于审计为准。前端展示该候选值并允许
编辑；最终名称仍由后端执行长度、空白和唯一性校验。发生极短时间内的名称冲突时，后端
生成或建议带短随机后缀的新名称，不把数据库约束错误直接暴露给用户。

### 配置与测试

提交配置后，系统通过一次性配置会话创建新的临时连接并立即测试。测试失败时保留同一个
临时连接，用户可以修改全部公开配置和秘密后重试；不得另外创建一串失败连接。

测试成功后，配置卡显示成功状态。对话继续收集实体类型和 MySQL 希沃目标，满足启动条件
后才显示任务确认卡。用户修改同步需求但未开始任务时，临时连接仍只属于当前对话。

### 放弃和结束

- 用户重置对话、连接配置会话过期或临时连接被新的临时连接替换时，旧临时连接立即禁用并
  撤销其秘密。
- 用户确认任务后，临时连接绑定该任务，不能再绑定其他任务。
- 钉钉数据成功固化为不可变任务快照后，立即撤销秘密。后续分析、执行和报告只使用固化
  数据，不再访问钉钉。
- 若任务在固化前失败或被终止，则在任务进入不可恢复的终态时撤销秘密。
- 等待人工澄清、审批或模型恢复不属于终态，不能提前撤销仍可能用于固化的秘密。

## 架构设计

### 连接作用域

为 API 连接增加明确的作用域与生命周期元数据：

- `scope`：`persistent` 或 `task_ephemeral`。现有记录迁移后默认为 `persistent`。
- `conversation_id`：临时连接创建时绑定的对话；持久连接为空。
- `task_id`：用户确认任务时原子绑定；绑定前为空，绑定后不可改为其他任务。
- `credentials_revoked_at`：秘密被撤销的时间；为空表示秘密仍可由受控运行时解析。
- `disabled_reason`：安全枚举，例如 `snapshot_materialized`、`conversation_reset`、
  `task_terminated`、`superseded` 或 `configuration_expired`。

数据库约束保证：

- `task_ephemeral` 必须有 `conversation_id`。
- `persistent` 不使用临时连接的对话和任务绑定字段。
- 一个临时连接最多绑定一个任务。
- 已撤销秘密的连接必须处于 `disabled` 状态。

历史连接保持 `persistent`，不会因为本功能上线而失效，但不会进入 AI 对话的钉钉任务候选
目录。

### 对话目录与模型契约

对话上下文仍向模型提供已注册 Provider，但钉钉连接目录只包含当前对话创建、尚未撤销且
作用域为 `task_ephemeral` 的连接。租户下的历史持久连接和其他对话的临时连接均不进入
`available_api_connections`。

当本轮消息明确要求钉钉同步，并且当前对话没有测试通过的临时连接时，服务端必须将模型
输出约束为 `api_configuration`。这项规则由后端验证器和对话 Skill 同时表达：

- Skill 指示模型每个新钉钉任务先返回安全配置卡。
- 后端拒绝模型选择持久连接、其他对话连接、已绑定连接或已撤销连接。
- 只有当前对话中测试通过且尚未绑定任务的临时连接才能生成 `start_confirmation`。

模型上下文、聊天消息和普通 API 响应继续只包含安全连接视图，不包含公开配置全文、
`secret_ref`、AppKey 或 AppSecret。

### 配置会话与连接创建

一次性配置会话增加预期作用域和当前对话绑定。创建临时钉钉连接时，后端在一个事务中：

1. 校验配置会话属于当前租户、当前操作员、当前对话和钉钉 Provider，且尚未消费和过期。
2. 校验完整公开配置和秘密字段。
3. 存储加密秘密，创建 `task_ephemeral` 连接，并绑定 `conversation_id`。
4. 消费配置会话。
5. 返回不含秘密的连接卡。

重新测试失败连接时允许轮换秘密和更新公开配置，但要求连接仍属于当前对话、尚未绑定任务
且尚未撤销。测试成功只将连接置为 `active`，不会自动创建任务。

### 任务创建与原子绑定

任务创建接口不信任前端传入的连接 ID。创建 API 来源任务时必须在同一数据库事务中锁定并
校验连接：

- 租户、Provider 和当前对话匹配。
- `scope == task_ephemeral`。
- 状态为 `active`，秘密未撤销。
- 尚未绑定其他任务。
- 测试时效、实体能力和可见数量满足任务选择。
- MySQL 目标与现有规则一致。

任务、`ApiAuthoritySourceRecord` 和连接的 `task_id` 在同一事务中写入。幂等重放返回原任务，
不会把连接再次绑定；使用新幂等键重复创建任务则返回安全冲突。

### 凭据撤销

凭据撤销是幂等的领域操作，不等同于删除审计记录。撤销流程：

1. 锁定临时连接及其秘密记录。
2. 校验调用方正在处理该连接绑定的对话或任务生命周期事件。
3. 删除或不可逆清除加密秘密内容，使现有 `secret_ref` 无法再解析。
4. 设置 `credentials_revoked_at`、`state = disabled` 和安全的 `disabled_reason`。
5. 记录不含秘密的审计事件。

`ApiAuthoritySourceRecord.frozen_secret_ref` 可以继续作为历史版本标识存在，但撤销后不能再
解析为凭据。固化成功后的幂等重放直接返回已发布快照，不需要重新解析秘密。

撤销触发点有两类：

- 固化成功：不可变来源文件和快照在事务中成功发布后，撤销连接秘密。
- 生命周期清理：对话重置、未绑定连接过期、任务在固化前失败或终止时撤销。

清理任务需要可重复执行并扫描过期但未撤销的临时连接，处理进程崩溃造成的遗漏。它只能
处理满足明确过期或终态条件的记录，不能按创建时间误删仍在运行或等待人工处理的任务秘密。

## 数据流

1. 用户发送“同步钉钉数据”。
2. 后端向模型提供钉钉 Provider，但不提供历史持久连接。
3. 模型返回 `api_configuration`，前端显示完整且重新初始化的配置卡。
4. 前端请求服务端生成默认连接名称，并创建绑定当前对话的一次性配置会话。
5. 用户提交完整公开配置、AppKey 和 AppSecret。
6. 后端创建新的临时连接并测试；失败时在同一连接上修改重试。
7. 测试成功后，模型只能选择当前对话的该临时连接并生成开始确认。
8. 用户确认后，后端原子创建任务并将临时连接绑定该任务。
9. Worker 使用冻结的秘密版本拉取钉钉数据并发布不可变快照。
10. 快照发布成功后立即撤销秘密；任务继续使用快照完成分析、治理与报告。

## 错误处理

- 配置会话过期：返回安全错误并生成新的配置卡，不复用已提交秘密。
- 名称冲突：返回可恢复的名称冲突信息和新的默认名称，不显示数据库异常。
- 连接测试失败：保留安全错误码，允许在同一临时连接上重新提交完整配置。
- 跨对话或跨租户引用：按不存在或禁止处理，不泄露连接元数据。
- 重复任务绑定：返回 `connection_already_bound`，不创建第二个任务。
- 已撤销连接：返回 `connection_credentials_revoked`，要求重新配置。
- 固化发布成功但撤销暂时失败：快照仍保持有效，连接进入待清理状态；幂等清理任务继续
  撤销，且该连接立即停止进入任何候选目录。
- 固化失败：不发布部分快照；只要任务仍可恢复就保留秘密，任务进入不可恢复终态后撤销。

所有响应、日志和审计事件继续禁止包含秘密、访问令牌、供应商响应正文和请求头。

## 安全边界

- AppKey/AppSecret 只从密码输入框进入一次性配置接口。
- 浏览器状态在提交成功或失败响应处理完成后清空秘密字段，不写入聊天、URL、本地存储或
  分析埋点。
- 模型只能看到 Provider、连接 ID、安全显示名、状态、能力和可见范围摘要。
- 后端运行时只能在连接未撤销且生命周期校验通过时解析秘密。
- 前端强制显示表单只是用户体验；真正的“不复用”由目录过滤、任务绑定校验和撤销机制共同
  保证。

## 测试策略

### 后端单元测试

- 钉钉 Provider 在没有当前对话临时连接时生成 `api_configuration`。
- 持久连接、其他对话连接、已绑定连接和已撤销连接不会进入当前对话候选目录。
- 默认名称满足格式、租户内唯一性和用户可修改要求。
- 临时连接创建要求完整公开配置和秘密字段。
- 凭据撤销幂等，并使 `secret_ref` 不可解析。
- 已发布快照的重放不依赖已撤销秘密。

### 后端集成测试

- 每次新对话钉钉任务均返回配置卡，即使租户已有活动持久连接。
- 同一对话测试失败后更新同一临时连接，不创建额外连接。
- 任务创建原子绑定连接；跨对话、重复绑定和撤销后绑定均失败。
- 固化成功后秘密立即撤销，任务后续阶段仍能完成。
- 固化前终止任务后秘密撤销。
- 等待人工处理时秘密不被清理。
- 对话重置和过期清理撤销未绑定秘密。
- 幂等任务请求仍返回同一个任务。

### 前端测试

- 每次钉钉同步都显示完整配置卡。
- 默认连接名称已预填且可以修改。
- 人员类型、根部门 ID、人员编号字段、班级字段和秘密不从上一任务继承。
- AppKey、AppSecret 使用密码输入框且必填。
- 学生模式显示班级字段，教师模式隐藏该字段。
- 测试失败后可修改完整配置并重试同一连接。
- 提交后秘密从组件状态清空，页面和消息中不出现秘密。

## 迁移与发布

1. 添加连接作用域、对话/任务绑定和撤销元数据，现有连接迁移为 `persistent`。
2. 先上线后端目录过滤、生命周期校验和兼容读取逻辑。
3. 上线完整重置的前端配置卡和默认名称接口。
4. 启用临时连接创建、任务原子绑定和固化后撤销。
5. 启用过期清理任务并监控安全错误码和待清理数量。

发布过程中，后端必须先于前端具备兼容能力。回滚时可停止创建新的临时连接，但不能重新
启用已撤销秘密；已创建任务继续使用已经发布的快照完成后续阶段。

## 验收标准

- 租户存在任意数量的历史活动钉钉连接时，新钉钉同步仍首先显示完整配置卡。
- 用户必须为每次任务重新提交组织参数、AppKey 和 AppSecret。
- 默认名称自动预填并允许修改。
- 一个临时连接最多创建一个任务，且不能跨对话使用。
- 新任务无法解析或复用任何已完成任务的凭据。
- 固化成功或不可恢复终止后，秘密不可再次解析。
- 对话、普通 API 响应、模型上下文、日志和审计事件中均不出现秘密。
