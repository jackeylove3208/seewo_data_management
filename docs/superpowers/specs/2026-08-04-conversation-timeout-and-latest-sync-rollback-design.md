# 对话超时与最近同步回滚资格设计

## 目标

修复 Agent 对话长期停留在“正在理解同步需求”的问题，并简化回滚资格规则：同一希沃目标一旦开始新的同步任务，所有更早同步记录立即失去回滚资格；只有最新一次已开始的同步任务在产生完整、可验证的成功报告后可以回滚。

## 已确认的业务规则

1. 回滚资格按租户和希沃目标数据源隔离。目标数据源由现有 `TargetDataSource` 规则识别：上传 CSV、数据库/API 配置或本地目标路径。
2. 新同步任务进入创建流程并建立任务记录后，即成为该目标的最新同步边界；不等待任务成功，也不判断任务是否实际产生字段变化。
3. 更早同步记录统一返回“记录过旧，无法回滚”，不再尝试恢复更早版本。
4. 最新同步任务只有在报告终态为 `completed` 且所有 mutation 都成功并验证有效时才可创建回滚任务。
5. 最新同步记录已经完成回滚时，仍返回“已经回滚；需下次同步后执行”。
6. 回滚预览和确认都必须重新检查同步边界；旧预览不能绕过新同步任务。

## 方案设计

### Agent 对话生命周期

当前对话接口是同步 HTTP 请求，前端在请求返回前一直保持 `collecting`。改动分为两层：

- 后端给一次对话模型处理设置总截止时间，超时后清理 `_message_in_flight`，持久化安全错误消息，并返回可重试的 `conversation_model_timeout`。
- 前端的消息 API 使用独立的 `AbortController` 和略长于后端的超时窗口。超时后将输入框恢复为可编辑状态，显示“对话理解超时，请稍后重试”，不继续显示无限 spinner。

模型调用继续保留结构化响应修复能力，但总截止时间覆盖语义重试和传输重试，避免当前 3 次语义尝试乘以 3 次传输尝试造成约 18 分钟等待。会话占用租约必须大于后端总截止时间，避免第一次请求仍在处理时第二条消息被错误接受。

### 回滚周期与最新同步边界

不新增一套平行的回滚表。继续使用 `AgentRollbackCycleRecord.generation` 做预览确认的并发栅栏，并新增 `record_sync_started(task)`：

- `AgentTaskService.create` 在同步任务 flush 成功后调用它，因此对话创建和手动创建共享同一规则；如果后续绑定或启动失败，事务回滚，旧资格不会被无故消耗。
- 已存在周期记录时递增 `generation`、清除已完成回滚标记，但保留 `latest_successful_sync_task_id` 给基线检查和成功报告使用。
- 回滚资格判断不再只看最近成功同步，而是查询该目标最近创建的同步任务（包括没有报告、失败或部分成功的任务）。候选源任务不是该最新任务时返回 `stale_sync_record`。
- 没有周期记录的旧数据通过历史任务查询同样判断最新同步边界，避免迁移前数据重新获得回滚资格。

这样可以满足“只要下一个任务开始，老任务就失效”，同时避免把尚未成功的同步误判为可回滚。

### 回滚执行错误

- 旧版模型驱动回滚执行后，按目标类型只调用数据库或 CSV 对应执行器；数据库回滚不再无条件追加 CSV 执行。
- 外部连接器冲突、能力缺失和外部写入结果不确定等回滚运行时错误转成持久化的 Agent 失败状态，释放学校锁和运行 claim，并记录安全错误码；不再让任务保持 `running` 后被 Worker 无限重新领取。
- 保留逐操作 checkpoint，重放仍可读取已完成操作；但失败必须有清晰的终态和错误事件，不能以缺少汇总报告的方式表现为“无响应”。

## API 与界面契约

后端 `rollback_blocked_reason` 增加 `stale_sync_record`。回滚预览接口对旧记录返回 HTTP 409 和错误码 `rollback_sync_record_too_old`，消息为：

> 该同步记录已过旧，只有最近一次同步记录可以回滚，请从最近一次同步任务发起回滚。

任务详情页对该状态禁用回滚按钮，显示“记录过旧，无法回滚”；`already_rolled_back` 的现有文案保持不变。前端 API 类型、任务详情测试和历史任务接口测试同步更新。

## 测试策略

- 对话：验证请求未返回时进入超时错误并恢复输入；后端模型总超时清理消息 claim；模型失败后错误消息可持久化并可重试。
- 回滚资格：验证新任务刚创建但未完成时，旧成功同步不可回滚；最新任务失败或部分成功时旧任务仍不可回滚；最新任务成功后可回滚；不同希沃目标互不影响；预览后开始新同步时确认失败。
- 回滚执行：验证 legacy 数据库路径不调用 CSV 执行器；连接器运行时错误使 run/task 进入 `failed` 并释放锁；逐操作 checkpoint 不影响终态记录。
- API/UI：验证 409 错误码和任务详情“记录过旧”提示；保留现有 `already_rolled_back`、跨目标和前端对话测试。

## 非目标

本次不改变身份匹配规则、模型分析合同、回滚操作的字段比较策略或人工审批数量；冲突跳过仍是安全无写入结果，不被改成强制写入。
