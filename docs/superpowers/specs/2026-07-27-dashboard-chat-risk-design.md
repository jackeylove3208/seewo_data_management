# 主页指标与聊天高风险展示设计

## 目标

修复主页对终止任务和问题数的错误统计，并让对话页展示 SQL 高风险治理操作的精简审批卡。

## 状态与指标口径

- 历史接口返回受控图的 `termination_requested` 事实。
- 只要终止请求已经由操作人批准，主页就把任务显示为“已终止”；后台可以继续生成终止报告。
- “治理操作成功率”定义为：已完成同步任务数 ÷ 全部未删除同步任务数。回滚任务不参与分子或分母。
- “待处理问题”只汇总未完成、已终止或失败任务的问题数；已完成任务和已删除任务不计入。
- 报告尚未生成时，历史接口使用当前任务已经持久化的 finding 数量；报告生成后使用报告中的 finding 事实。

## 聊天高风险审批

- 对话页为 `agent-graph-v1` 任务轮询 `/graph`，以服务端 human gate 为唯一审批事实。
- 只展示 `risk=high` 且类型为 `high_risk_approval` 的审批卡。
- 卡片只展示人员或记录名称、操作类型、字段修改前值和修改后值。
- 不展示 AI 分析、风险解释或治理方案。
- 待审批卡提供“同意”和“拒绝”；提交成功后显示“已同意”或“已拒绝”。
- 已由精简审批卡展示的高风险 gate 不再重复显示泛化的 `approval_required` 事件操作区。
- 审批继续提交冻结的 `graph_cursor` 和 `membership_hash`，避免 stale cursor 和越权审批。

## 错误处理

- `/graph` 暂时失败时保留现有任务进度，下一轮继续请求。
- 审批失败时保留按钮并显示中文错误，不提前标记为成功。
- 缺少 cursor、membership hash 或明细的审批卡不可操作，并显示“审批信息不完整”。

## 验证

- 后端历史接口测试覆盖实时 finding 数、终止请求和报告优先级。
- 主页组件测试覆盖同步任务成功率、回滚排除、完成任务问题排除、终止/失败问题计入。
- 对话组件测试覆盖高风险精简字段、同意/拒绝契约、成功状态和重复事件抑制。
