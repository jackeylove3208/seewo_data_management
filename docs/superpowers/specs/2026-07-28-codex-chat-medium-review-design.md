# Codex 风格对话与中风险复核设计

## 目标

新建对话采用更宽的 Codex 风格布局：用户消息位于右侧，助手消息位于左侧，任务处理状态继续固定在右侧。聊天窗口必须直接承载中风险批量复核，任务进入终态后必须恢复普通对话，并允许在保留上下文的同一对话中启动下一项同步任务。

## 布局与消息

- 页面使用可用视口宽度，不再限制在约 980px；主内容最大宽度为约 1440px。
- 对话区和右侧任务状态栏使用 `minmax(0, 1fr) 280px` 布局。
- 助手消息左对齐，使用头像、角色名和无厚重气泡的正文排版。
- 用户消息右对齐，使用蓝灰色紧凑气泡，与助手消息形成清晰区分。
- 任务状态栏保持右侧可见；小屏幕下允许压缩宽度，但不覆盖输入框和终止按钮。
- 输入框固定在对话区底部，宽度与消息内容区一致。

## 聊天内中风险复核

- Graph 返回的全部 `high_risk_approval` 且 `risk=medium` Gate 合并为一个中风险复核框。
- 每个 Finding 默认状态为同意；用户可以逐项勾选“拒绝此项”。
- 每项只展示人员或部门、操作类型、修改字段及前后值，不展示冗长分析。
- 未勾选拒绝时，主按钮为“全部同意并继续”。
- 存在拒绝项时，按钮显示同意数和拒绝数，并通过批量 Gate API 一次提交。
- 每个 Gate 继续携带冻结的 `graph_cursor`、`membership_hash` 和 Finding 清单；证据不完整时 fail-closed。
- 提交后复核框保留并显示完成状态，避免用户误以为点击无效。

## 终态续聊与连续任务

- `completed`、`terminated`、`failed` 均为终态，不再锁定普通聊天输入。
- 任务运行、等待人工、模型阻塞或终止处理中，普通输入仍保持锁定；身份冲突说明是唯一临时开放的输入。
- 终态后发送的消息继续使用当前 Conversation 的完整历史。
- 如果模型生成新的同步确认，前端在旧终态任务仍可见的情况下展示确认卡，并允许启动下一任务。
- 后端恢复当前 Conversation 时，如果最新 Run 已进入终态，仍应恢复最新的 `start_confirmation`，不能因为 Conversation 曾经存在 Run 而丢失确认状态。
- 新任务创建后替换右侧当前任务状态，旧任务继续保留在左侧历史中。

## 错误处理

- 中风险批量提交失败时保留当前勾选状态，并显示后端错误。
- 缺少 Graph Cursor、membership hash 或 Finding 清单时禁止提交。
- 终态后的模型调用失败沿用现有对话错误展示，不清空旧任务或聊天历史。

## 验证

- 组件测试覆盖默认全部同意、逐项拒绝、混合批量提交和提交后状态。
- Conversation 页面测试覆盖中风险 Gate 出现在聊天、右侧状态栏仍存在、终态输入解锁、终态后新确认和第二任务启动。
- 后端 API 测试覆盖存在终态 Run 时恢复 Conversation 的新启动确认。
- 运行前端全量测试、lint、typecheck、build；后端全量 pytest、ruff、mypy。
