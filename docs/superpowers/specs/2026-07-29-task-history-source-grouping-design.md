# 按希沃数据源分组任务历史

## 背景

当前左侧工作区和主页“最近任务”都把同步、回滚、失败和终止任务平铺展示。随着任务增加，
同一个希沃目标的多次治理记录会被其他任务打散，用户难以判断一条回滚属于哪个同步链路，
也难以查看某个希沃数据源的完整治理时间线。

本次变更把“希沃目标数据源”作为历史记录的一级分组，把同步和回滚任务作为分组内的时间线。
分组必须由后端根据稳定目标标识生成，前端不得根据任务标题、文件显示名称或第三方来源猜测。

## 目标

- 左侧历史记录按希沃目标数据源展示多个可折叠任务列表。
- 主页最近任务使用相同分组和排序规则。
- 同一希沃目标的同步、终止、失败与回滚任务始终进入同一分组。
- 数据源名称可变化，但不得改变稳定分组身份。
- 不同数据源即使同名也不得错误合并。
- 无法恢复目标身份的旧任务仍可查看，但必须明确归入“其他历史任务”。

## 不在本次范围

- 不按第三方权威来源建立一级分组。
- 不增加学校登录、学校切换或跨租户历史。
- 不改变任务删除、终止、回滚资格和治理执行规则。
- 不修改任务锁；全校仍只允许一个排他任务运行。
- 不增加数据源管理、重命名或合并功能。
- 不改变历史接口的分页策略。

## 方案选择

采用“数据源时间线”方案：

- 左侧侧栏以折叠组展示最近任务。
- 主页以较完整的折叠组展示当前加载的全部历史任务。
- 最近活跃的数据源排在最前。
- 每个分组内的任务按创建时间倒序排列。
- 默认展开当前任务所属的数据源；没有当前任务时展开最近活跃的数据源。

不采用纯数据源卡片总览，因为查看具体同步或回滚任务会多一次导航。不采用前端临时按名称
归类，因为文件同名、连接器改名和回滚标题都会产生错误归类。

## 稳定数据源身份

### 后端所有权

后端为每条历史任务返回一个服务端生成的目标数据源描述：

```json
{
  "target_source": {
    "key": "opaque-stable-key",
    "name": "希沃组织主库",
    "kind": "database",
    "identified": true
  }
}
```

`key` 是租户内稳定且不透明的分组键。客户端只允许比较该字段，不得解析、构造或覆盖它。
`name` 只负责显示，可以在后续配置调整时变化。`kind` 仅用于显示数据库、授权 CSV 或临时
上传图标。`identified` 表示该任务是否成功关联到一个明确的希沃目标。

分组键必须包含后端可信 `OperatorContext.tenant_id` 的作用域。同一目标在不同租户中绝不
共享分组。接口不得返回服务器绝对路径、数据库凭据、DSN 或秘密引用。

### 各连接方式的判定

- 数据库目标：以 `tenant_id + target.configuration_id` 作为稳定身份材料。
- 本地授权 CSV：以 `tenant_id + 后端规范化的 target.source_ref` 作为稳定身份材料。
- 临时上传 CSV：以 `tenant_id + target.upload_id` 作为稳定身份材料。两次上传即使文件名
  相同也属于两个不同目标，不能合并。
- 回滚任务：必须继承原同步任务的目标分组，优先通过 `parent_task_id` 解析，不能根据回滚
  标题或回滚操作重新归类。
- 旧任务：当目标引用缺失、父任务缺失或旧格式无法解析时，返回固定的未识别分组键，
  `name` 为“其他历史任务”，`kind` 为 `unknown`，`identified` 为 `false`。

分组键应由稳定身份材料经过确定性摘要生成，避免把授权路径或配置内部标识直接暴露给浏览器。
显示名称与分组键分离：

- 数据库优先使用服务端配置的显示名称；当前配置没有显示名称时使用配置 ID 的安全名称。
- 本地授权 CSV 使用安全的逻辑来源名称或文件名，不显示授权根目录的绝对路径。
- 临时上传 CSV 使用“临时上传 · 原始文件名”。
- 回滚使用原同步任务解析出的数据源名称。

### 名称冲突

两个不同分组可能具有相同显示名称。前端仍按 `key` 分开显示，并使用连接类型或安全短标识
作为辅助文案，不能因为名称相同而合并。

## 后端设计

### 目标数据源解析器

新增一个职责单一的历史目标解析器，输入任务及其必要关联记录，输出目标数据源描述。解析器：

1. 校验任务属于当前可信租户。
2. 回滚任务先解析父同步任务。
3. 从同步任务不可变的 `agent_intent.target` 读取连接类型及稳定引用。
4. 从服务器配置或已保存的文件元数据生成安全显示名称。
5. 对稳定身份材料生成租户内不透明分组键。
6. 解析失败时返回未识别分组，不抛弃整条历史任务。

历史 API 调用解析器并为每个 `AgentHistoryItem` 增加 `target_source`。接口继续返回扁平任务
数组；分组由前端完成。这样保留当前删除刷新和任务导航逻辑，同时让侧栏、主页复用同一份
纯前端分组函数。

解析回滚时应预加载父任务，避免按任务逐条查询产生 N+1。CSV 显示名称所需的文件元数据也
应批量读取。

### 兼容性

`target_source` 是历史响应的新增必填对象，但前端映射层仍为本地旧缓存提供未识别兜底。
其他任务详情、报告和治理 API 不改变。没有数据库迁移需求，稳定身份来自任务中已经持久化
的目标引用。

## 前端数据模型与分组

`TaskHistoryItem` 增加：

- `targetSourceKey`
- `targetSourceName`
- `targetSourceKind`
- `targetSourceIdentified`

新增纯函数 `groupTasksByTargetSource(tasks)`：

1. 使用 `targetSourceKey` 建组。
2. 分组内按 `createdAt` 倒序排列。
3. 分组的 `lastActivityAt` 取最新任务时间。
4. 分组按 `lastActivityAt` 倒序排列。
5. 计算任务数、进行中数、失败数和待处理问题数，用于组标题摘要。
6. 输入顺序、任务标题和数据源名称不得影响归类结果。

后端历史是权威数据。本地缓存仅作为接口不可用时的显示兜底；缺少目标字段的缓存任务进入
“其他历史任务”，不得根据 `targetFile` 猜测。

## 左侧工作区

- “历史记录”下展示数据源折叠组，而不是平铺任务。
- 侧栏继续只取最近八条任务，保持现有信息密度；这八条任务按目标来源重新分组。
- 默认展开当前路由任务所属分组；没有选中任务时展开最近活跃分组。
- 用户可以独立展开或收起其他分组。
- 每条任务保留状态点、日期、问题数、删除按钮和详情链接。
- 同步与回滚使用不同的小型类型标识，但位于同一数据源分组。
- 删除任务后立即从分组移除；空分组同时消失。
- “查看全部历史”继续进入主页完整历史。
- 整个侧栏收起时只保留现有紧凑导航行为，不在窄栏中强行展示多层文字。

## 主页最近任务

- 页面指标继续按任务事实计算，避免本次改动改变指标业务含义。
- “最近任务”区域改为完整的数据源折叠列表。
- 每个组标题显示数据源名称、类型、任务数、最近活动时间，以及进行中或失败摘要。
- 展开后显示原任务行信息，包括任务类型、标题、来源方向、问题数、状态、时间和删除能力。
- 默认展开最近活跃的数据源，其余收起。
- 删除最后一条任务时，整个数据源组从页面消失。
- 任务进行中、终止、失败或完成都只影响任务状态和组摘要，不改变归类。

## 状态与错误处理

- 历史接口完全失败时，沿用本地缓存兜底，旧缓存统一进入“其他历史任务”。
- 单条任务目标解析失败时只降级该任务，不让整页历史失败。
- 回滚父任务不存在时进入“其他历史任务”，并保留回滚任务自身的查看和删除限制。
- 两个不同分组同名时必须同时展示。
- 无任务时显示当前空状态，不渲染空的数据源折叠标题。
- 删除请求失败时保留任务及分组，并继续显示现有后端错误信息。

## 可访问性与响应式

- 数据源组标题使用原生按钮语义或具备 `aria-expanded` 的等价控件。
- 每个组使用稳定键关联可访问名称和内容区域。
- 键盘可以聚焦、展开组并进入任务。
- 展开状态不能改变任务详情链接和删除按钮的可操作性。
- 移动端保持单列；组标题摘要允许换行，但数据源名称不得溢出容器。

## 测试要求

### 后端

- 数据库任务按目标配置 ID 生成相同分组。
- 不同数据库配置即使同名也生成不同分组。
- 本地授权 CSV 同一 `source_ref` 生成相同分组。
- 两次同名临时上传因 `upload_id` 不同而生成不同分组。
- 回滚继承父同步任务分组。
- 缺失父任务或旧目标结构降级到“其他历史任务”。
- 分组响应不泄露绝对路径、DSN、凭据或秘密引用。
- 历史 API 新字段的租户隔离和响应合同通过。

### 前端

- 纯分组函数只按稳定键归类并按最新活动排序。
- 同名不同键保持两个分组。
- 侧栏默认展开当前任务所属组。
- 主页默认展开最近活跃组。
- 同一组同时显示同步和回滚任务。
- 删除最后一条任务会删除空分组。
- 后端失败时旧本地缓存进入“其他历史任务”。
- 折叠按钮、任务导航和删除操作具备键盘与可访问名称。

### 端到端

- 创建同步任务后立即出现在对应希沃数据源组。
- 为已完成同步创建回滚后，回滚出现在同一组而不是新分组。
- 切换其他页面再返回，分组和任务导航仍正确。
- 两个不同希沃目标的任务不会互相混入。

## 验收标准

1. 用户可以在侧栏和主页按希沃目标快速找到同步与回滚时间线。
2. 同源归类不依赖标题或显示名称。
3. 同名不同源、同名重复上传和回滚任务均不会误归类。
4. 旧任务仍可访问，且未识别状态清晰。
5. 现有删除、终止、详情、报告和回滚能力不发生回归。
