# 终止状态与报告可见性设计

## 目标

用户确认终止任务后，前端必须明确说明治理流程已经停止；后续进入报告阶段仅用于生成终止总结，
不能让用户误以为治理执行或回滚仍在继续。报告生成后，入口必须出现在任务详情页顶部可见区域。

## 任务状态展示

- 当 Agent Graph 已收到终止请求但尚未完成终止报告时，在任务标题下方展示提示卡：
  “任务已终止，正在为你生成终止报告。已完成的修改将被保留，未开始的操作不会继续。”
- 此时阶段轨道中的最后阶段显示“生成终止报告”，不显示“报告与回滚”。
- 正常完成的同步任务继续使用“报告与回滚”；独立回滚任务继续使用“报告与回滚”。
- 终止提示只依据后端持久化事实，例如 `termination_requested`、终止节点或最终
  `terminated` 状态，不依赖短暂的前端本地状态。

## 顶部报告卡

- 当任务响应包含 `report_id` 时，在任务标题和阶段轨道之间展示报告卡。
- 终止任务的卡片标题为“终止报告已生成”，正常任务为“任务报告已生成”，回滚任务为
  “回滚报告已生成”。
- 卡片展示任务终态，并提供“查看任务报告”主按钮。
- 删除事件列表底部原有的孤立报告按钮，避免两个入口产生位置不一致。
- 报告尚未生成时保留终止提示；轮询取得 `report_id` 后自动替换为报告卡，不需要刷新页面。

## 错误与降级

- 模型报告生成失败但后端生成了降级报告时，仍展示报告卡；报告页负责显示已持久化事实。
- 报告接口读取失败不影响任务终态，报告页继续展示现有错误提示。

## 测试

- 终止请求处理中展示明确的终止报告提示和“生成终止报告”阶段名称。
- 已终止且具有 `report_id` 的任务在顶部展示“终止报告已生成”和查看按钮。
- 报告入口不再出现在任务事件列表之后。
- 正常同步任务和回滚任务保持各自正确的报告标题。
