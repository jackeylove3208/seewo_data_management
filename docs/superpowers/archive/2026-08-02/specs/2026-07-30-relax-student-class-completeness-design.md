# 放宽第三方学生班级完整性约束

## 目标

第三方权威学生缺少班级时仍视为有效数据并参与身份对齐。学生仍必须具有类别、姓名、学号、电话和邮箱；教师与部门的必填规则保持不变。

## 接入与规范化

服务端权威数据校验不再把学生 `class_name` 加入必填字段。规范化 Skill 使用同一规则：缺少班级的第三方学生输出 `invalid=false`，但不得猜测或补造班级。

类别仍用于识别部门、学生和教师。固定六字段合同与字段映射保持不变，本次只放宽学生行的班级值完整性，不允许缺少其他必填字段。

## 对齐与治理

有效学生继续使用学号、电话和邮箱建立身份索引。身份确认后，如果第三方班级为空而希沃班级非空，系统保留现有班级字段差异，并生成“将希沃班级设置为空”的更新候选。

该候选由服务端判定为中风险，并与其他中风险项一起显示。审核项明确携带 `selection_mode=opt_in`：

- 默认不批准该项，保留希沃现有班级；
- 用户勾选“将班级设置为空”后才批准；
- 未勾选的 finding 按 rejected 处理，不进入执行计划。

普通中风险项继续采用现有 `opt_out` 行为：默认批准，勾选表示拒绝。

## Skill 约束

更新组织数据规范化 Skill，明确第三方学生班级可为空。更新对齐与治理相关 Skill，明确第三方班级为空、希沃班级非空时可以生成中风险清空候选，但只能由用户主动选择。

## 接口与前端

中风险审核项增加 `selection_mode`，取值为 `opt_in` 或 `opt_out`。后端依据持久化事实设置该字段，前端不自行推断治理策略。

中风险审核卡同时支持两种选择语义：

- `opt_out`：默认执行，勾选“拒绝此项”后不执行；
- `opt_in`：默认保留，勾选“将班级设置为空”后执行。

提交时仍复用现有 approved/rejected finding 集合和冻结成员校验，不改变执行与幂等合同。

## 测试

- 第三方学生仅缺班级时不产生完整性标记。
- 第三方学生缺少类别、姓名、学号、电话或邮箱时仍被排除。
- 教师和部门缺少原有必填字段时仍被排除。
- 第三方班级为空、希沃班级非空时形成中风险 `opt_in` 审核项。
- `opt_in` 项未勾选时提交 rejected，勾选后提交 approved。
- 普通中风险项维持现有默认批准行为。

## 非目标

- 不修改 OpenSpec。
- 不放宽固定六字段映射合同。
- 不修改教师、部门或希沃数据的有效性规则。
- 不引入通用多方案审批模型。
